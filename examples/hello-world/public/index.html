What you're seeing

  1. Page issues a nonce. GET /api/nonce returns a single-use random string the backend keeps tied to your session. Replay defense — every JWT must carry this exact nonce.
  2. Wallet produces a JWT. Mock wallet generates an ECDSA P-256 keypair, derives did:mata:<base58-pubkey> from it, self-signs the genesis roster, and mints a JWT against your rpOrigin + nonce + requested claims.
  3. Backend verifies. @matanetwork/sovereign-id-verify runs the four-step check entirely locally: genesis self-signature → roster chain → head VM → JWS signature. Zero MATA HTTP traffic.
  4. RP backend anchors on first sight. The DID + genesis roster hash + current version go into the user table; on subsequent sign-ins the backend asserts the same DID still produces the same genesis hash.
